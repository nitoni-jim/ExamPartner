# ExamPartner Backend — working notes for Claude

FastAPI backend for ExamPartner (Nigerian WAEC/NECO/JAMB exam prep). Deployed on Render, database on Neon PostgreSQL. Solo-maintained.

Read this before changing anything in `backend/`. Most of what follows is not style preference — it is the set of mistakes that fail **silently** in this codebase.

---

## Layout and imports

```
backend/
  app.py            FastAPI app, router registration, init_db() at startup
  config.py         all env/config — import from here, never os.getenv inline
  db.py             schema + connections (see the warnings below)
  routes/           one module per area, each exporting `router`
  services/         business logic
  tests/            pytest; conftest.py puts backend/ on sys.path
  tools/ scripts/   one-off utilities
```

Imports are **flat** — `sys.path` root is `backend/`, so it is `from config import ...`, `from db import ...`, `from services.foo import ...`. No package prefix.

Get a connection with `db_conn()` from `config`, not `get_db` from `db`:

```python
from config import db_conn
```

`paystack_routes.py` predates these conventions — it calls `get_db()` directly and switches placeholders by engine (`ph = "%s" if _using_postgres() else "?"`). It works; do not copy it.

New route module: define `router`, import it in `app.py` as `from routes.x import router as x_router`, then `app.include_router(x_router)` with a short trailing comment saying what it is.

## The database — read this twice

### Dual engine, always

`DATABASE_URL` set → Postgres. Absent → SQLite. **Production is Neon Postgres; SQLite is local dev.** Both must work.

`db.py` declares schema as Python column lists and applies it idempotently — `CREATE TABLE IF NOT EXISTS` plus `ADD COLUMN IF NOT EXISTS`. **There is no Alembic and no migration files.**

`ADD COLUMN IF NOT EXISTS` never changes the type of a column that already exists. To change an existing Postgres column's type, add it to `_POSTGRES_COLUMN_TYPE_CHANGES` in `db.py`, which alters it on the next `init_db()` and is a no-op once applied. `questions.marks` going from `INTEGER` to `DOUBLE PRECISION` is the worked example.

Schema changes go in **two places**: `_init_db_sqlite()` and `_init_db_postgres()`. Add the column list once, then wire it into both branches. Forgetting one branch means the table is correct in dev and wrong in production, or the reverse, with no error.

Type mapping across the two:

| Concept | SQLite | Postgres |
|---|---|---|
| timestamp | `TEXT` | `TIMESTAMPTZ` |
| boolean | `TEXT` `"1"`/`"0"` | `BOOLEAN` |
| autoincrement id | `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` |

### Placeholders are `?`, never `%s`

`_PGCursor.execute()` rewrites `?` → `%s` on the way to psycopg2. Write `?` everywhere, both engines. A literal `%s` breaks SQLite.

### There is no `rollback()`

`_PGConn` exposes only `cursor()`, `commit()`, `close()`. The house pattern is:

```python
db = db_conn()
try:
    cur = db.cursor()
    ...
    db.commit()
finally:
    db.close()
```

Closing without committing is the only rollback available. **Do not write logic that depends on an explicit rollback or a nested transaction.**

### Index DDL failures are swallowed

Every index in `db.py` runs inside `try/except` — a savepoint on Postgres, a per-statement commit on SQLite — and a failure is logged as a `warning` and skipped. That is fine for performance indexes.

**It is not fine for a unique index that enforces a business rule.** If a correctness-critical constraint belongs in the schema, create it outside the best-effort loop where the exception propagates, and assert its existence at startup. A capacity or uniqueness guarantee that silently failed to install is worse than no guarantee, because the code above it assumes it holds.

Licensing is the exception to "fail at startup": this backend also serves the live Android app, so a licensing schema failure is caught by `init_db()`, logged at ERROR, recorded (`db.licensing_status()`, shown on `/health`), and **licensing closes while everything else starts**. The guarantee is then enforced where bindings are written: any path that creates a binding or changes a binding's `installation_id` calls `db.licensing_index_present(cur)` inside its own transaction and refuses with 503, as `claim_capacity()` does. Never gate on the startup flag alone.

### NULLs are distinct in unique indexes

Both engines treat `NULL != NULL` for uniqueness, so a unique index over a nullable column does **not** deduplicate rows where that column is NULL. `paper_rules` learned this the hard way — see the comments on `ux_paper_rules_unique_row_v2` and the four-branch predicate in `upsert_paper_rule()`. If row identity involves a nullable column, the real guard is an explicit `IS NULL` branch in the lookup, not the index.

Also: `CREATE UNIQUE INDEX IF NOT EXISTS` is a **no-op when the name already exists**, even if the definition differs. To widen an index, `DROP INDEX IF EXISTS` the old name and create a new versioned name (`..._v2`). Otherwise existing databases keep the old definition forever.

### Timestamps read back differently per engine

Written from Python as `datetime.now(timezone.utc).isoformat()`. They come back as **`str` on SQLite and `datetime` on Postgres**.

So `row["expires_at"] > datetime.now(timezone.utc)` works on Postgres and raises `TypeError` on SQLite. `access_control.is_paid_user()` had exactly this shape until it was routed through `to_datetime()` in `services/licensing_time.py`, which is the helper to use. Normalise before comparing, and **compare in Python, not in SQL** — lexicographic ISO comparison happens to work until a format varies, then fails quietly.

## Service and route conventions

- Services **raise `HTTPException` directly**. There is a known future refactor toward `{"data": ...} | {"error": ...}`, but it has not happened — do not introduce it in one module in isolation.
- Services return `{"ok": True, ...}` dicts.
- IDs on newer tables: `secrets.token_hex(16)` into `TEXT PRIMARY KEY`. Only the older `users` / `payments` / `admin_audit_log` tables use integer autoincrement. **Do not use `SERIAL`** — it is not portable to SQLite.
- Each service defines its own `_row_to_dict(row)` handling both `sqlite3.Row` and psycopg2 `RealDictRow`. Copy the version in `paper_rules_service.py`.
- Auth is enforced at the **route** layer via `require_admin(user)` from `services/access_control.py`. Admin is `ADMIN_IDENTIFIERS` in config, or `users.is_admin`.
- Never let a client-supplied id imply authority. Resolve the object, then check ownership.
- Validate write inputs in the **service**, not the route — the service is what a future bulk-import path will call, and a route-level check would be bypassed. `upsert_paper_rule()` shows the pattern.

## Dependencies

- `requirements.txt` is **production**. Render runs `pip install -r requirements.txt`. Anything added here ships to the live service.
- `requirements-dev.txt` pulls in production via `-r requirements.txt` and adds `pytest`, `httpx` and `pyflakes`. `httpx` is pinned deliberately to the version `anthropic` already resolves, so local and production agree.
- Pin exact versions, matching the existing style.
- `cryptography` is **not currently a dependency**. Signing work needs it added to `requirements.txt`.

## Tests

`pytest` from `backend/`. `tests/conftest.py` puts `backend/` on `sys.path` and provides:

- `auth_headers` — a signed-in user, token minted with the app's real `make_token()`
- `other_auth_headers` — a **different** signed-in user
- `auth_identifier` — the identifier `auth_headers` authenticates as
- `pg_database` — points `DATABASE_URL` at the local throwaway Postgres from `TEST_DATABASE_URL` (local hosts only; **fails, never skips**, when unset) and runs `init_db()`
- `sqlite_database` — a fresh initialised SQLite file, with both `DB_PATH` bindings set
- `make_pool` — factory for a licensing account plus seat pool on whichever engine is active

Use `other_auth_headers` for any ownership or isolation test. Proving user A cannot read user B's data needs two real identities; one identity plus a missing header only proves that unauthenticated access is refused.

Existing cheap safety nets worth keeping green: `test_app_imports.py` and `test_no_undefined_names.py`.

Concurrency behaviour must be tested **against Postgres**. SQLite serialises writes at the database level and will pass tests that Postgres would fail.

## Comments are load-bearing — do not tidy them

This codebase is unusually comment-dense, and the comments record specific production failures and the reasoning that resolved them: why `theory_attachments` is a separate table from `theory_attempts`, why `rubric_groups_json` exists, why R2 instead of S3, why `supports_country` is a capability flag rather than a version check, why `paper_rules` row identity is a 2×2 matrix.

Several say, in effect, *"the sloppier version of this claim was made first and was wrong."* That is institutional memory for a solo developer with no colleague to ask.

**Do not condense, reflow, or delete these while editing nearby code.** If you change behaviour a comment describes, update the comment to match — and if you discover something the hard way, write it down in the same style.

## Scope discipline

- Do not refactor adjacent code while implementing a feature. Change what the task needs.
- Do not reformat files. No import reordering, no whitespace sweeps — they bury the real diff.
- Cross-cutting changes (the error-envelope refactor, timestamp normalisation) land as their own deliberate piece of work, not as a side effect.
- Android and the web frontend are **not in this directory**. `frontend/` is the PWA; the Android app is a separate codebase.
- A cloud Linux session **cannot build Windows client code**. Do not attempt it.
